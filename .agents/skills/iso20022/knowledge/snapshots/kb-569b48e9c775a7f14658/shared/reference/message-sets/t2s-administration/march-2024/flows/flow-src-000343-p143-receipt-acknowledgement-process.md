# Receipt Acknowledgement Process

Source context: T2S Administration. This reference preserves the source-defined segment and its evidence.

## Purpose, trigger and conditions

### Definition

Receipt Acknowledgement is generated by Central System and sent to a directly connected Participant to inform about a rejection of a message. It is generated only by the Central System. Within Central System this message is generated after a negative authentication process. It can be also sent as an error reporting response to a report query or resend request and as a validation result notification to a resend request.   

Evidence: [T10](../documents/src-000343/tables/tbl-0010.md), source row 2.

### Trigger

The process is triggered by Central System when a CB, CSD or any party authorised sends a message which leads to a rejection of the Central System platform.

Evidence: [T10](../documents/src-000343/tables/tbl-0010.md), source row 3.

### Pre-conditions

This message is sent by Central System for the following reasons:  Missing Authentication; Inbound Processing Rejections; Rejection Resend; Validation Result Resend; Oversize and timeout; Report Detail Query Response; Query Queuing Information. 

Evidence: [T10](../documents/src-000343/tables/tbl-0010.md), source row 4.

### Post-conditions

The Receipt Acknowledgement is sent by Central System not by any other party involved in the process.

Evidence: [T10](../documents/src-000343/tables/tbl-0010.md), source row 5.

### Role

System Transaction Administrator 

Evidence: [T10](../documents/src-000343/tables/tbl-0010.md), source row 6.
