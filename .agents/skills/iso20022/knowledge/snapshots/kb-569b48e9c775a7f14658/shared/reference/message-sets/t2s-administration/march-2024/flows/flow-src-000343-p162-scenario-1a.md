# Receipt acknowledgement — receipt status

[src-000343](../../../../../../evidence/omitted/e6546c5f64c53f963440988a.md) archive member `ISO20022_MDR_Target2Securities_August_2026_v1/Target2-Securities_Administration_MessageSet/ISO20022_MDRPart1_Target2Securities_Administration_2023_2024_v2.docx`; Description of BusinessActivities / Receipt Acknowledgement (admi.007) / Scenario 1a.

## Purpose, trigger, preconditions and outcomes

[T10](../documents/src-000343/tables/tbl-0010.md)

| Item | Description |
| --- | --- |
| Definition | Receipt Acknowledgement is generated by Central System and sent to a directly connected Participant to inform about a rejection of a message. It is generated only by the Central System. Within Central System this message is generated after a negative authentication process. It can be also sent as an error reporting response to a report query or resend request and as a validation result notification to a resend request.    |
| Trigger | The process is triggered by Central System when a CB, CSD or any party authorised sends a message which leads to a rejection of the Central System platform. |
| Pre-conditions | This message is sent by Central System for the following reasons:  Missing Authentication; Inbound Processing Rejections; Rejection Resend; Validation Result Resend; Oversize and timeout; Report Detail Query Response; Query Queuing Information.  |
| Post-conditions | The Receipt Acknowledgement is sent by Central System not by any other party involved in the process. |
| Role | System Transaction Administrator  |


## Participants and responsibilities

[System Member](../../../../participants/participant-src-000343-system-member.md) initiates the query, resend request or original A2A message; [System Transaction Administrator](../../../../participants/participant-src-000343-system-transaction-administrator.md) performs the central-system checks, delivery and applicable response. P150/P155/P161 establish contextual institutional mappings; those mappings do not merge the role definitions.

## Source narrative

**P161** Note: In the frame of the Central System workflows, System Transaction Administrator corresponds to the settlement infrastructure, the System Member to the Central System-Participant.

**P163** The ReceiptAcknowledgement message can be used to provide a processing status of the initial message. In response the System Transaction Administrator can sent a rejection or an acknowledgement status message (as a kind of a successful receipt).

## Header and file context

P86 uses BAH with ReportQueryRequest and ResendRequest. P87 says ReceiptAcknowledgement is generally sent without BAH, with BAH attached when it responds to ReportQueryRequest. P88 lists missing authentication, inbound processing rejection, oversize/timeout and query-queuing scenarios without BAH. P90 says Business File Header can bundle one or more business messages and acknowledges negative validation of a message or whole file. These are publication-specific usage statements, not a universal rule inferred from header schemas.
